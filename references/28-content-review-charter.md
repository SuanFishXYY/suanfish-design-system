# 📜 ref 28 · 生成内容评价审核制度 v1.0.0

> *规则集（ref 15/16/19）回答「这条对不对」；本制度回答「这整件东西能不能放行」。*
> *生成物 = 任何 agent / 议会产出的设计稿、spec、plan、copy、report。把它当「法案」审。*

## 版本同步契约

| 字段 | 说明 |
| --- | --- |
| `charter_version` | 本制度的 semver |
| `bound_to_ruleset_version` | 对应 ref 15/16/19 三份规则集的 `ruleset_version`（取三者最高） |

**ui-auditor 在 G5 蓝军终审加载本制度时会检查同步**。如果 `bound_to_ruleset_version` 落后于 ref 15/16/19 当前任一 `ruleset_version`，G5 直接挂起（输出 `CHARTER_OUT_OF_SYNC`），强制 owner 先同步本制度（新增/废弃的 R 规则可能改变 G3「合规」维评分口径 + G5 否决依据）。同 ref 15 `RULESET_OUT_OF_SYNC` 套路——制度与规则集不得脱节。

> **G5 跑两把同步刀，别混**：① 本制度的 **charter↔ruleset** 检查——`bound_to_ruleset_version` 落后 → `CHARTER_OUT_OF_SYNC`（管「制度对不对得上规则集版本」，见本节）；② 继承 ref 15/16 的 **ruleset↔token** 检查——`bound_to_token_version` 落后 → `RULESET_OUT_OF_SYNC`（管「规则集对不对得上令牌版本」，见 §2-G5 / ref 15 契约）。两个字段、两个码、两层 owner，挂起时按码定位该谁同步。

## 0. 制度一句话

> **每件生成物立案 → 减法派⟷加法派辩论 → 6 维 rubric 打分 → 议会 2/3 投票 → 蓝军 P0 终审一票否决 → 放行 / 退回。六步走完才算交付，少一步叫自嗨。**

## 1. 适用范围与分级

| 等级 | 触发条件 | 走完整六步？ | 备注 |
| --- | --- | --- | --- |
| **S 级（正式稿）** | P0 交付 · 对外发布 · 合并到 main · 涉及令牌/动画/结构改动 | ✅ 全流程 | 高 token，值得 |
| **A 级（评审稿）** | P1 交付 · 跨 agent 协作 · 多方案择优 | ✅ 但议会规模减半 | 省token |
| **B 级（草稿）** | P2 交付 · 单 agent 内部迭代 · 探索性 | ⚡ Fast-track（见 §7） | 跳辩论，只跑 G1+G5 |
| **C 级（ scratch）** | 临时草稿 · 笔记 · 未对外 | 🚫 免审 | 作者自负 |

> **task_kind 由 user-declared 优先**（防 LLM 自利路由把自己降级逃审，同 v4.2 议会规矩）。作者不得自行把 S 级降 B 级。

## 2. 六步流水线

```
┌──────────────────────────────────────────────────────────────┐
│ G1  立案    生成物 + BRIEF + 验收标准 → 提交议会挂号            │
│ G2  辩论    减法派 ⟷ 加法派 各出 1 份意见（≤300 字）            │
│ G3  评分    6 维 rubric，每位参会圣人独立打分（0-5）            │
│ G4  投票    2/3 多数 = 通过门控；平票 / 不足法定人数 = 退回      │
│ G5  蓝军    debunk-auditor + ui-auditor P0 致命缺陷终审         │
│            P0 命中 → 一票否决（哪怕议会全票通过）              │
│ G6  放行    PASS → 合并/签收 ｜ FAIL → 退回重做（带缺陷清单）   │
└──────────────────────────────────────────────────────────────┘
```

### G1 · 立案
- **必须随附**：① 生成物本体 ② BRIEF（用户原始诉求）③ 验收标准（可证伪的 checklist）④ task_kind / 等级声明。
- 缺 BRIEF 或验收标准 → **立案要件不全**，直接退回补全（G1 完整性硬门 · 非 R18：R18 管「矛盾两端都站·没选倾向」，不管缺件）。
- 挂号产出 `case_id`，后续所有记录挂在 `case_id` 下，可追溯。

### G2 · 辩论
- **减法派**：主张能删什么、能简化什么、能不能不做（质疑需求本身）。
- **加法派**：主张该补什么、边界 case、完整性缺口。
- 两派**强制对立**，禁止单一圣人一票否决（v4.2 议会规矩），但任一派可提「P0 致命缺陷动议」直接升级到 G5。
- 输出：两份 ≤300 字意见，进 `辩论纪要`。

### G3 · 评分（6 维 rubric）
每位参会圣人**独立**打分，0-5 分，取中位数（非均值，抗极端值）：

| 维度 | 5 分（满分） | 0 分（红线） | 主审 agent |
| --- | --- | --- | --- |
| **准确** | 事实/数据/引用全可证伪 | 引用捏造、数据造假 | debunk-auditor |
| **完整** | 4 态状态机全 / 边界 case 全覆盖 | 只有 happy path | empty-state-storyteller |
| **原创** | 不抄既有模式 / 有增量价值 | 复制粘贴反模式 | ui-architect |
| **合规** | 令牌/动画/结构全在规则集内 | R 规则命中（ref 15/16/19） | ui-auditor |
| **一致** | 与系统现有风格/哲学层一致 | 风格漂移、哲学层断裂 | brand-keeper / token-keeper |
| **价值** | 解决真问题、ROI 为正 | 伪需求、R1-R25 命中 | sage_congress 集体 |

- 单维 0 分（红线）→ **该维主审 agent 可直接动议退回**，无需等投票。
- 加权总分 = Σ(维度分 × 权重)，权重见 §5。S 级门槛见 §4。

### G4 · 投票
- **法定人数**：S 级 ≥ 3 类圣人（4:4:4 均权三大类中至少 3 类有代表）；A 级 ≥ 2 类。
- **通过线**：2/3 多数（同 v4.2 议会）。
- **平票 / 法定人数不足** → **退回**，不搁置、不默认通过（防止「没人反对就过」的偷懒）。
- 投票必须带理由（「通过/否决 + 一句话」），匿名计票但理由公开进 `投票记录`。

### G5 · 蓝军终审（一票否决层）
议会通过**不代表放行**。蓝军独立跑两把刀：

| 蓝军 | 职责 | 否决触发 |
| --- | --- | --- |
| **ui-auditor** | 跑 ref 15/16/19 规则集，🟥 严重级命中 | 任何 R 规则命中 |
| **debunk-auditor** | 疾虚妄，找伪智能/伪个性化/装腔 | R23 命中 |

- 蓝军**不参与 G4 投票**，只在 G5 行使一票否决——制衡议会「集体通过但集体翻车」。
- 蓝军否决必须给出**可证伪的定位**（文件:行 / 规则编号 / 复现路径），否则否决无效（防蓝军滥权）。
- **规则集不同步**（`bound_to_token_version` 落后）→ ui-auditor 输出 `RULESET_OUT_OF_SYNC`，审计直接挂起，强制 owner 先同步规则集（同 ref 15 契约）。

### G6 · 放行 / 退回
- **PASS**：G4 通过 + G5 无否决 → 签收，`case_id` 进归档，附 `评分卡 + 投票记录 + 辩论纪要 + 蓝军报告`。
- **FAIL**：任一门未过 → 退回，**必须附缺陷清单**（哪一维/哪条规则/谁主审/怎么改）。退回不带清单 = 3.25，等于白退。
- **退回后追踪**：FAIL 即触发 [ref 29 整改闭环追踪制](29-remediation-loop-charter.md)——缺陷清单拆工单 → owner 认领 → 修复 → 复审 → 销项。退回不进 ref 29 = 缺陷黑盒，等于踩红线一。
- 退回重做 ≥ 2 次 → 自动升级一档（B→A→S），并触发 §8 复盘。

## 3. 与现有 R/W/H 规则集的关系

> **规则集 = 单条规则的 grep；本制度 = 整件生成物的门控。正交，不替代。**

```
ref 15/16/19 (R/W/H)          ref 28 (本制度)
─────────────────────         ─────────────────────
R 命中 → 单条拒绝     ───┐
W 命中 → 警告放行      ───┼──→ 都汇入 G3「合规」维 + G5 蓝军
H 命中 → 观察不阻断    ───┘     作为评分输入 / 否决依据
```

- **R 规则命中**：直接被 G5 ui-auditor 否决，根本到不了投票。
- **W 规则命中**：G3「合规」维扣分（≤2 分），不自动否决，但拉低总分。
- **H 规则命中**：进 `缺陷清单` 提示项，不阻断，归档可查。

## 4. 评分门槛（S 级正式稿）

| 门槛 | 值 | 不过则 |
| --- | --- | --- |
| 加权总分 | ≥ 4.0 / 5.0 | 退回 |
| 任一维度中位数 | ≥ 2.5 | 退回（短板红线） |
| 「合规」维 | R 规则零命中（≠ 强制满分 5；W 命中仅扣分拉低总分，不强制退回，见 §3） | 退回（仅 R 命中触发） |
| 「准确」维 | ≥ 4（防虚妄） | 退回 |
| G4 投票 | ≥ 2/3 | 退回 |
| G5 蓝军 | 零否决 | 退回 |

> **「短板红线」**：总分高但某维 0-1 分（如原创 5 分但准确 1 分 = 引用造假），照样退回。防止用强项掩盖致命短板——这叫端到端，不叫平均分主义。

## 5. 维度权重（默认 · 可按 task_kind 覆盖）

| 维度 | 权重 | 说明 |
| --- | --- | --- |
| 准确 | 0.25 | 事实错误 = 雪崩，权重最高 |
| 合规 | 0.20 | 规则集是底线 |
| 完整 | 0.15 | 边界 case |
| 一致 | 0.15 | 系统性 |
| 原创 | 0.15 | 增量价值 |
| 价值 | 0.10 | ROI（议会集体判） |

> task_kind 可调权重，但「准确 + 合规」合计不得低于 0.40——底线不让步。

## 6. 输出物清单（每件生成物归档必备）

```
case_id/
├── 01_brief.md          ← G1 立案（生成物 + BRIEF + 验收标准）
├── 02_debate.md         ← G2 辩论纪要（减法派 / 加法派）
├── 03_scorecard.md      ← G3 评分卡（6 维 × 每位圣人打分 + 中位数 + 加权总分）
├── 04_vote.md           ← G4 投票记录（票数 + 通过/否决理由）
├── 05_bluearmy.md       ← G5 蓝军报告（ui-auditor + debunk-auditor）
└── 06_verdict.md        ← G6 放行/退回判定 + 缺陷清单（如退回）
```

> **没有 06_verdict.md 的「已完成」= 踩红线一（空口完成）**。归档缺件 = 审计未闭环。

## 7. Fast-track（B 级草稿快速通道）

简单事不养闲圣人（同 v4.2「简单事 2 个圣人就够，省 80% token」）：

```
G1 立案 → 跳 G2/G3/G4 → G5 蓝军（仅 ui-auditor 跑规则集）→ G6 放行
```

- **前提**：task_kind 明确声明 B 级 + 单 agent 内部迭代 + 不涉令牌/动画/结构。
- **降级逃审检测**：若 G5 发现生成物实际触动 S 级范围（如偷偷改了令牌），**就地升级走全流程**，并对作者记一次「自利路由」警告。

---

## 8. 复盘机制（退回 ≥ 2 次触发）

退回重做不是终点。同一 `case_id` 退回 ≥ 2 次，强制四步复盘（同阿里复盘法）：

1. **回顾目标**：BRIEF 和验收标准当初对齐了吗？
2. **评估结果**：哪一维反复挂？是同一短板还是漂移？
3. **分析根因**：是需求不清、方案选错、还是执行偏差？上一次改对地方了吗？
4. **沉淀规律**：若同类短板重复出现 → 提 **新规则 PR** 进 ref 15/16/19，让规则集吃下这个教训（把个案沉淀为制度）。

> **一个问题进来，一类问题出去。** 修完不沉淀规则，下次同样的坑再炸一次。

## 9. 边界 case 与冲突裁决

| 情形 | 裁决 |
| --- | --- |
| 议会全票通过但蓝军否决 | **蓝军胜**。G5 是否决层，制衡议会。议会可申诉一次，申诉仍被否决 = 退回。 |
| 蓝军内部冲突（ui-auditor 通过、debunk-auditor 否决） | **任一蓝军否决即否决**（保守优先）。 |
| 减法派 / 加法派都打 0 分（双方都认为该否） | 跳过 G4，直接退回（罕见但合法）。 |
| 法定人数凑不齐 | **退回**，不默认通过。挂「待议」≤ 1 轮，仍凑不齐 = 退回。 |
| 规则集 `RULESET_OUT_OF_SYNC` | 审计挂起，强制 owner 同步规则集后重跑 G5。 |
| 作者对退回不服 | 可提一次申诉，附新证据，由另一组圣人复评。复评为终审。 |

## 10. 制度自检（owner 季度执行）

每季度由 sage_congress owner 跑一次制度 Keeper Test：

- [ ] 过去 N 件 S 级生成物，退回率是否合理？（过高=规则集太严或需求不清；过低=审核放水）
- [ ] 蓝军否决率是否 > 0？（长期 0 否决 = 蓝军形同虚设，红色警报）
- [ ] 退回 ≥ 2 次的 case 是否都产出了新规则 PR？
- [ ] Fast-track 有没有被滥用降级逃审？

> 制度本身也要被审——不审审核者，审核就会腐烂。这一条由 [ref 30 M 轨元审计](30-posthoc-governance-charter.md)收口：M 轨定期校准评分圣人 + 审蓝军否决率 + 审核者 Keeper Test 下岗。本制度（入口门）+ [ref 29](29-remediation-loop-charter.md)（退回门）+ [ref 30](30-posthoc-governance-charter.md)（事后门）= 三道门端到端闭环。
