# 📜 ref 30 · 事后治理双轨制 v1.0.0

> *ref 28 管入口门，ref 29 管退回门——但放行 ≠ 永远正确，议会 ≠ 永远不腐烂。*
> *本制度补第三道门：事后门。双轨并行——K 轨查内容（衰弱了没），M 轨查审核者（腐烂了没）。两轨交叉喂食，闭环套闭环。*

## 版本同步契约

| 字段 | 说明 |
| --- | --- |
| `charter_version` | 本制度的 semver |
| `bound_to_ruleset_version` | 对应 ref 15/16/19 三份规则集的 `ruleset_version`（取三者最高） |

**K2 复审 / M2 校准时检查同步**。规则集升级会直接改变 K 轨「用最新规则集审旧内容」的判定口径 + M2 锚点样例的标定分。若 `bound_to_ruleset_version` 落后 → 输出 `CHARTER_OUT_OF_SYNC`，meta-auditor 强制 owner 同步本制度 + 刷新 M2 锚点样例后重跑。规则集大版本升级（跳 major）同时是 K1 事件触发条件（见 §2 K1）。

## 0. 制度一句话

> **放行不是终点。K 轨定期抽审已合并内容，衰弱就 CULL 下架；M 轨定期校准审核者，失准就下岗。K 的下架率喂给 M 判松严，M 的元审发现喂给 K 重采样。三道门（28 入口 / 29 退回 / 30 事后）齐了，制度才端到端。**

## 2. K 轨 · 归档复审（查内容衰弱）

> 放行的内容会衰弱——令牌版本变了、规则集升级了、外部引证推翻了、设计趋势过时了。没人定期复审 = 知识库慢性腐烂。

### K1 · 风险分层采样
每月由 ui-auditor 从归档池按风险分层抽样（不是均抽，高风险多抽）：

| 风险层 | 采样率 | 判定标准 |
| --- | --- | --- |
| **高危** | 30% | 涉及令牌/动画/结构 + 被外部依赖多 + 最近一次复审 > 2 版本前 |
| **中危** | 10% | 单 agent 产出 + 中等引用 |
| **低危** | 3% | 探索性/草稿/低引用 |

**额外触发采样**（不按月度，事件驱动）：
- 令牌升级（`bound_to_token_version` 任何变更 · 含新增 dark mode 等令牌集的小版本升级）→ 触发该版本绑定内容全采。旧内容当时令牌齐全不代表现在齐全。
- 规则集升级（ref 15/16/19 增删 R 规则）→ 触发命中该规则的历史内容全采。
- **M3 元审发出"某圣人失准"信号** → 该圣人近期放行的内容强制全采（交叉喂食入口）。
- 外部引证推翻（社区/用户反馈某设计过时）→ 点名采样。

### K2 · 复审
- 重跑 ref 28 的 6 维 rubric（准确/完整/原创/合规/一致/价值）+ ref 15/16/19 规则集。
- **用最新规则集审旧内容**——旧内容当时合规不代表现在合规。
- 复审员**不得是原放行议会成员**（防自打脸放水），由 meta-auditor 指派独立复审组。

### K3 · 判定四态

| 判定 | 含义 | 处置 |
| --- | --- | --- |
| **存活** | 仍达标 | 续用，刷新 `last_reviewed` 时间戳 |
| **衰弱** | 分数下降但未跌破红线 | 进 ref 29 整改闭环（开 W 级工单限改） |
| **过时** | 规则集/令牌已变，结构性不兼容 | CULL 下架 + 标注「历史参考，勿复用」 |
| **被推翻** | 外部引证/数据证伪（如原 DAU 预测错了） | CULL 下架 + 通告（防误用） |

- **CULL 下架是红线动作**：必须 meta-auditor + 对应 owner 双签，在归档目录标 `status: CULLED` + 下架理由 + 替代方案指向。不得静默删除。
- **衰弱 → ref 29**：K3 判定衰弱即开整改工单，走 ref 29 R1-R5，复用同一套 SLA。

### K4 · 下架通告
- 被推翻/过时的下架内容，发**全工作室通告**（防其他 agent 还在引用过期设计）。
- 通告挂在 `archive/cull-notice/` 下，含：被下架内容 ID + 理由 + 替代方案 + 影响范围（谁在引用）。

## 3. M 轨 · 元审计（查审核者腐烂）

> 议会和蓝军本身会腐烂——圣人打分会通胀（越来越松）、蓝军会形同虚设（长期零否决）、复审员会放水（怕打脸）。不审审核者，审核就腐烂。ref 29 §10 自己点名的收口。

### M1 · 双盲打分
- ref 28 G3 评分时，**隐去生成物作者 + 隐去派别标签**，防光环效应（"这是大佬做的，给高分"）。
- 双盲仅对 G3 评分圣人生效；G2 辩论派别标签必须保留（辩论本就需要立场）。
- **meta-auditor**（新增角色）负责维护双盲映射表，事后解盲。

### M2 · 锚点校准（检测分数通胀）
每季度，meta-auditor 用一组**固定锚点样例**（已知好坏的标定生成物）测各圣人打分：

| 信号 | 判定 | 动作 |
| --- | --- | --- |
| 某圣人对"已知差样例"持续打高分 | 放水/通胀 | 校准警告 + 该圣人近期打分打 0.8 折扣 |
| 某圣人对"已知好样例"持续打低分 | 过严/偏见 | 校准警告 + 复核其否决是否合理 |
| 全议会平均分季度环比上升 > 0.3 | 系统性通胀 | 全局校准 + 调高 G4 通过门槛 |
| 全议会平均分季度环比下降 > 0.3 | 系统性过严 | 排查规则集是否过载 |

- **K3 下架率交叉喂入**：若 K 轨下架率高 → 喂给 M2 判断"是审太松了（放行一堆要下架的）"。若下架率长期 = 0 → 喂给 M2 判断"是 K 轨形同虚设，还是真的都达标"（红色警报）。

### M3 · 元审（meta-auditor 审议会 + 蓝军）
meta-auditor 独立于 sage_congress，定期审两件事：

1. **审议会**：法定人数是否凑齐？投票理由是否敷衍？有没有"集体通过但集体翻车"的 case？退回 ≥2 次的 case 是否走了 ref 28 §8 复盘？
2. **审蓝军**：ui-auditor / debunk-auditor 否决率是否 > 0？（长期零否决 = 蓝军腐烂）否决是否都带可证伪定位？（防滥权）

- **M3 发现 → 反哺 K1**：若发现某圣人持续失准 → 该圣人放行的内容强制进 K1 重采样（交叉喂食另一入口）。

### M4 · 蓝军互攻（对冲）
每季度，两把蓝军**互相当红军攻击**：
- debunk-auditor 攻 ui-auditor：规则集执行有没有漏？有没有该拦没拦的？
- ui-auditor 攻 debunk-auditor：R23 疾虚妄有没有滥杀？有没有把合理设计误判为"伪智能"？

互攻发现 = 双方都开整改工单进 ref 29。防蓝军抱团或互相放水。

### M5 · 审核者 Keeper Test
审核者（圣人 / 蓝军 / 复审员）本身也走 Keeper Test——失准就下岗：

| 角色 | Keeper 触发 | 后果 |
| --- | --- | --- |
| 评分圣人 | M2 校准警告 ≥ 2 次 / 季度 | 暂停投票权 1 轮，重训锚点 |
| 蓝军 | M3 发现长期零否决 or 滥权否决 | 该蓝军当季否决权冻结，由替补蓝军顶上 |
| 复审员 | ref 29 R4 抽检发现放水 | 暂停复审资格，进 M2 重校准 |

> **🔴 M5 弹劾投票避嫌律（v4.2.7 哲理审计 R5 · 补套娃闭环）**：M5 动议「需 sage_congress 2/3 仲裁通过才执行」(§M 轨权限)，但被弹劾的评分圣人**正是 sage_congress 议会成员**——若不避嫌，等于被弹劾者投票决定自己要不要被弹劾，违 ref 30:202「不能让 sage_congress 审自己」红线。补避嫌：
> - 被弹劾圣人**本人 + 其师承链上下 1 跳**(ref 27 invited 链) 强制回避投票，不计入分母。
> - 弹劾仲裁议会由**三大类各 top-N 重新选拔一组未被牵连的厚仙人**组成（动态常委机制复用），非原被审议会自审。
> - 蓝军/复审员被弹劾同理回避（蓝军 ui-auditor↔debunk-auditor 互攻时双方互回避，由对方+独立组仲裁）。
> - 避嫌后法定人数不足 → 不搁置、不默认不弹劾，扩召独立组补齐（同 G4 平票处理逻辑），防「凑不齐就放过」。
> - **🔴 扩召优先级（v4.2.7 哲理审计 R6 · 补避嫌律算术交互）**：扩召补齐**先类别后人数**——须保证仲裁议会满足 G4 法定人数的**类别覆盖**（S 级≥3 类有代表 / A 级≥2 类），再补人数到 2/3 通过线。理由：哲学类板凳 335 位最厚，若扩召默认按"分高优先"会偏向抓哲学类，可能凑齐人数却只 1 类代表→不满足 S 级≥3 类→触发 G4"凑不齐退回"→而 M5 弹劾不能退回（退回=放过失准圣人，违制度初衷）→死循环。故扩召**强制每类先取 ≥1 位未被牵连厚仙人**保类别覆盖，再按分补人数；某类确实全员被牵连（极罕见，如哲学类某学派师承链整体失准）→ 该类记"缺类"上报，降级处理（S 级弹劾转 A 级法定人数≥2 类·如实记录回避范围，不伪造类别覆盖）。
> - **🔴 降级边界与防滥用（v4.2.7 哲理审计 R7 · 补 R6 降级逃审风险）**：R6 缺类降级**只降 G4 法定人数的类别要求**（S级≥3类→A级≥2类），**不降其他**：① 通过线仍 2/3（ref 28 §G4 通过线不分 S/A 级，降级不放松弹劾门槛）；② **议会规模不减半**（ref 28 §1 A 级"议会规模减半"是省 token 优化，不适用于 M5 弹劾——弹劾议会规模保持原 S 级规模，保证 2/3 票数基数不被稀释，防"降级→减半→2/3 实际票数变少→实质放松弹劾"）；③ 不引入 ref 28 §4 的 S 级评分门槛（加权总分/短板红线/准确维）——那些是"生成物放行"门槛，M5 是"投票弹劾"门控，套用对象不同，不混。**防故意制造缺类逃审**：缺类判定**不得由被弹劾方自报回避名单**——回避名单（被弹劾圣人 + 师承链上下 1 跳）由 **meta-auditor 独立核验师承链真实性**（ref 27 invited 链可追溯，禁臆造师承扩大回避范围人为造"全员被牵连"）。缺类降级需在 `archive/meta-audit/` 公开记录：缺哪类 + 回避名单 + 师承链证据，受全工作室监督（同 meta-auditor 元审报告公开机制）。

> **套娃制衡**：审核者本身被审出问题，其问题 case 走 ref 28 六步 + ref 29 整改——审核者也是被审对象，没有谁凌驾于制度之上。

## 4. 双轨交叉喂食（灵魂）

> 两轨不是各跑各的，是互相喂数据。这是双轨制区别于"两个独立制度"的关键。

```
        K 轨 (查内容)                    M 轨 (查审核者)
┌─────────────────────┐         ┌─────────────────────┐
│ K1 采样 ─→ K2 复审   │         │ M1 双盲 ─→ M2 校准   │
│      ↑               │         │      ↑    ↓          │
│      │               │         │      │    │          │
│      │   K3 下架率 ────────────→│  (审太松还是太严？)  │
│      │               │         │      │              │
│      │   M3 元审发现 ←────────────│  (该圣人放行的       │
│  (强制重采样该圣人内容)│         │   内容重点复审)      │
│      ↓               │         │      ↓              │
│ K3 判定 ─→ K4 下架    │         │ M3 元审 ─→ M5 下岗   │
└─────────────────────┘         └─────────────────────┘
              ↓                            ↓
         衰弱→ref29 整改            失准→ref28/29 套娃
```

| 喂食方向 | 数据 | 触发动作 |
| --- | --- | --- |
| K → M | K3 下架率 | M2 判松严：下架率高=审松，长期零=K轨虚设 |
| K → M | K2 复审分 vs 原放行分 | M2 检测原审圣人是否通胀（同一内容分掉了） |
| M → K | M3 某圣人失准信号 | K1 强制全采该圣人放行的内容 |
| M → K | M4 蓝军互攻发现 | K1 重采被该蓝军放行的内容 |
| K → ref29 | K3 衰弱 | 开 W 级工单走 ref 29 R1-R5 |
| M → ref28/29 | M5 审核者下岗 | 该审核者的待办 case 重派 + 其历史 case 抽查 |

## 6. meta-auditor 角色

> 元审计需要独立于被审对象——不能让 sage_congress 审自己。
> 角色定义见 [`agents/meta-auditor.md`](../agents/meta-auditor.md)（v4.2.7 落地）。流程编排由 [`review-orchestrator`](../agents/review-orchestrator.md) 负责，meta-auditor 只管 M 轨「审审核者」，二者正交（见 meta-auditor.md §与 review-orchestrator 的边界）。

- **独立性**：meta-auditor 不参与 ref 28 G4 投票、不参与 ref 29 R4 复审，只审"审的过程"。
- **权限**：可调阅任意 case_id 的完整记录（01-06 + remediation/）；可发起 M5 下岗动议（需 sage_congress 2/3 仲裁通过才执行）。
- **制衡 meta-auditor 自身**：meta-auditor 的元审报告本身要进 `archive/meta-audit/` 公开，受全工作室监督；其自身失准由 sage_congress 集体仲裁（套娃止于此层，不无限递归）。
- **哲学锚**：王充 · 疾虚妄（同 debunk-auditor 同源，但 debunk 审生成物，meta 审审核者——一把刀的两面）。

## 8. 边界 case 与冲突裁决

| 情形 | 裁决 |
| --- | --- |
| K3 判下架，但原作者不服 | 申诉一次，由独立复审组（非原作者议会）复评。复评为终审。 |
| M2 校准判定某圣人通胀，圣人辩称"是样例过时了" | 样例由 meta-auditor 每季度刷新，过时辩称成立则刷新锚点重测，不成立则校准生效。 |
| M4 蓝军互攻，双方互相否决对方放行的内容 | 都进 ref 29 整改，由 meta-auditor 仲裁谁对——不得互相包庇。 |
| meta-auditor 自身失准（被怀疑放水审审核者） | sage_congress 集体 2/3 仲裁，可弹劾 meta-auditor。套娃止于此层。 |
| K 轨下架内容被其他 case 依赖 | 下架前先扫依赖图，依赖方一并标记"引用已下架"，强制进 K1 重采。 |
| 双轨交叉喂食数据冲突（K 说审松、M2 说审严） | 不合并，并列上报，由 meta-auditor + sage_congress 联合诊断根因（可能是规则集本身有问题）。 |

## 9. 制度自检指标（季度 · meta-auditor 出 dashboard）

| 指标 | 健康区间 | 异常信号 |
| --- | --- | --- |
| K 轨下架率 | 2%-8% | 长期 0 = K 轨虚设；> 15% = 上游 ref 28 放行太松 |
| K 轨衰弱→ref29 转化率 | 5%-15% | 偏高 = 内容衰减快，规则集可能迭代太激进 |
| M2 校准警告数 | 每季度 < 全圣人 10% | 偏高 = 评分体系系统性失准 |
| 蓝军否决率 | > 0 且 < 20% | 长期 0 = 蓝军腐烂（M3 红警） |
| M4 互攻命中率 | 5%-15% | 长期 0 = 蓝军抱团；偏高 = 蓝军互相拆台 |
| M5 下岗数 | 偶发 | 频繁 = 审核者培训/选拔机制有问题 |
| 交叉喂食触发次数 | > 0 | 长期 0 = 双轨各跑各的，没交叉，制度退化成两个独立制度 |

> 最后一条是**双轨制的命门**——交叉喂食不触发，双轨就退化成两个独立的 K 和 M，失去了"闭环套闭环"的灵魂。

## 10. 三道门闭环总检（年度 · sage_congress + meta-auditor 联合）

年度检视整套内容评价制度（ref 28+29+30）是否端到端运转：

- [ ] 入口门（ref 28）：放行率是否合理？有没有 case 绕过六步？
- [ ] 退回门（ref 29）：退回的 case 是否都销项了？僵尸工单清理了吗？屡犯提规则 PR 了吗？
- [ ] 事后门（ref 30 K轨）：下架率健康吗？衰弱内容进 ref 29 了吗？
- [ ] 审核者门（ref 30 M轨）：评分通胀了吗？蓝军腐烂了吗？meta-auditor 自身被监督了吗？**sage_congress 自身被监督了吗？**（meta-auditor 审议会，议会仲裁 meta-auditor——这层双向闭环避嫌做了吗？M5 弹劾投票有没有回避被弹劾圣人？）
- [ ] 交叉喂食：K↔M 数据流还在流吗？还是退化成独立两轨了？
- [ ] 套娃止层：meta-auditor 之上有 sage_congress 仲裁兜底，没有无限递归。

> 三道门 + 双轨交叉 + 套娃止层 = 端到端闭环。任何一道门长期不运转，整套制度就会从那一道开始腐烂。
