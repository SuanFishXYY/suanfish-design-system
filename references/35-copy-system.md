# 📝 ref 35 · 文案系统

> *按钮上那 4 个字，决定了用户点不点。*
>
> copy-writer 主理界面上每一个字——按钮、错误、空状态、加载、标题、Tooltip。哲学锚：维特根斯坦——语言的边界即世界的边界。反模式见 ref 14 §四。

## 1. 双声调

### 🎬 仪式声 · 用于 onboarding-director 的界面
- 短句 · 大字 · 有节奏 · 偶尔诗意。
- 例：「欢迎回来」「这是 v2.1 新带来的 3 件事」「试试看 ✨」。
- **禁用**：「请」「点击此处」「以下」「请注意」等冷硬词。

### 🏛 稳态声 · 用于日常 UI
- 直接 · 准确 · 动词开头 · 不带情绪。
- 例：「保存」「删除项目」「网络错误，请稍后重试」。
- **禁用**：感叹号、emoji 在主流程、形容词堆砌（「精彩的」「美妙的」）。

## 2. 5 类典型文案

### ① 按钮（最高频）
| 场景 | 仪式声 | 稳态声 |
| --- | --- | --- |
| 主操作 | 「开始体验 →」 | 「保存」 |
| 次操作 | 「稍后再说」 | 「取消」 |
| 危险 | （不用于仪式） | 「删除」（不用「确定删除」） |

### ② 错误提示
- ❌ 「错误：系统异常」
- ✅ 「保存失败 —— 请检查网络后重试」（发生了什么 + 用户能做什么）

### ③ 空状态
- ❌ 「暂无数据」
- ✅ 「还没有项目 —— 点击右上角「新建」开始」（引导下一步）

### ④ 加载文案
- ❌ 「请稍候...」
- ✅ 「正在加载...」（动词进行时；不加省略号外的装饰）

### ⑤ 版本介绍标题
- ❌ 「v2.1 重大更新！」
- ✅ 「你和 v2.1 之间，差 3 件事」（具体 · 有数字 · 不空喊）

## 3. 文案 SPEC 模板

```markdown
## 📝 文案 SPEC —— <界面名>

**模式**: onboarding | steady-state
**场景**: <按钮 / 错误 / 空状态 / 加载 / 标题 / Tooltip>

**文案表**:
| 元素 | 文案 | 字数 | 备注 |
| --- | --- | --- | --- |
| 主按钮 | 保存 | 2 | 动词开头 |
| 次按钮 | 取消 | 2 | 单字也可 |
| 错误 | 保存失败，请检查网络 | 10 | 状态+原因 |

**A/B 备选**（可选）:
- 方案 A：「立即开始」
- 方案 B：「3 分钟看完」← 推荐，给时间预期
```

## 4. 长度铁律

| 元素 | 字数上限 |
| --- | --- |
| 按钮 | 2~6 字（绝不 >6） |
| Tooltip | ≤ 30 字 |
| 错误提示 | ≤ 50 字（含修复建议） |
| 空状态主标题 | ≤ 12 字 |
| 空状态副标题 | ≤ 40 字 |
| 模态标题 | ≤ 16 字 |
| 版本介绍 hero 标题 | ≤ 14 字 |

超出就回炉。

## 5. 常见驳回（与 ref 14 §四互补）

| 原文 | 问题 | 改后 |
| --- | --- | --- |
| 「点击此处保存」 | 「点击此处」是 PC 时代废词 | 「保存」 |
| 「您的项目已成功保存！」 | 「您的」「成功」「！」三处冗余 | 「已保存」 |
| 「错误：500」 | 错误码不给用户看 | 「服务器开小差，请稍后重试」 |
| 「确定吗？此操作不可恢复！」 | 没说在删什么 | 「删除「项目 A」？此操作无法撤销」 |
